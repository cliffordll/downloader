# AVDownloader 浏览器扩展（本地开发版）

Chrome 和 Edge 共用此目录。扩展在播放视频时观察网络响应，列出当前标签页的 M3U8 / MP4 地址，并发送到本机 AVDownloader 的创建任务弹窗。

## 安装

1. 启动本仓库的新版下载器：在项目根目录运行 `python main.py`，使用已安装 `requirements.txt` 依赖的 Python。
2. Chrome 打开 `chrome://extensions`；Edge 打开 `edge://extensions`。
3. 开启“开发者模式”，点击“加载已解压的扩展”（Edge 也可能显示“加载解压缩的扩展”）。
4. 选择 **`D:\works\demo\downloader\extension`**，即包含 `manifest.json` 的目录。
5. 可在浏览器扩展菜单中固定“AVDownloader 视频地址助手”。

不需要注册商店账号。更新源码后，在扩展管理页点击重新加载；重新加载会清除部分会话数据；配对码保留，必要时刷新网页重新播放。

候选列表支持地址关键词和类型（全部 / M3U8 / MP4）组合筛选，关键词不区分大小写。筛选只改变显示，不删除隐藏的地址；“清空当前页”会清空该页所有候选，包括被筛选隐藏的地址。

## 配对和使用

1. 在下载器点击工具栏“浏览器扩展配对”（拼图图标，位于“下载 MP4”右侧），或选择“文件 → 浏览器扩展配对…”，复制弹窗中的完整配对码，然后关闭弹窗。
2. 点击浏览器扩展图标，展开“连接下载器”，填写与下载器一致的端口，粘贴配对码，点击“保存配置”。
3. 打开视频网页，**刷新网页后播放视频**。必须在安装扩展后产生新的网络请求。
4. 点击扩展图标，选择候选地址，点击“添加任务”。“复制地址”用于复制完整网址；“删除”仅移除当前标签页中的该条候选，不影响下载器中已创建的任务。网页再次请求同一地址时，可能重新捕获。
5. 回到下载器确认保存目录和文件名。M3U8 先点击“获取 M3U8”，成功获取列表后点击“下载”；MP4 确认后直接开始下载。M3U8 沿用现有流程，创建后在任务列表点击开始。

发送成功表示地址已进入下载器待确认队列，**不代表下载完成或任务已经创建**。其他模态弹窗打开时，候选会等待弹窗关闭后显示。队列最多 10 项。

配对码保存在下载器用户目录的 `browser-pairing.json`（Windows 为 `~/.avdownloader/browser-pairing.json`，Mac 同样使用此路径）和扩展的 `chrome.storage.local` 中。下载器与浏览器重启后不必重新配对。首次启用过连接后，下载器重启会自动恢复本机接收服务；退出时服务关闭。浏览器完整退出后仅清除捕获的地址。

需要使旧码失效时，在下载器配对窗口点击“重置配对码”，复制新码并在扩展中重新保存。重置会清空尚未读取的接收队列。

端口默认 `17839`。端口被占用时，在下载器配对窗口修改“监听端口”并点击“应用”，再在扩展中填写相同端口并保存配置。成功切换不会改变配对码或丢弃待确认地址；失败时保留原监听和配置。端口范围为 `1～65535`，设置保存在原配对文件和扩展本地存储中，重启继续使用。升级此版本后首次使用需保存下载器当前显示的配对码；随后长期有效。

## 捕获规则与权限

- 使用 Manifest V3 的 `webRequest`，观察 HTTP/HTTPS 响应，不修改网页请求；无需内容脚本。
- 按 `.m3u8` / `.mp4` 路径后缀或 M3U8 / MP4 响应 MIME 类型识别，保留完整查询参数。
- 每个标签页最多保留 100 个地址，同一完整网址去重。带不同签名参数的网址分别保留。
- 地址存储于 `chrome.storage.session`，后台工作线程重启后仍可读取；刷新/导航到新页面、关闭标签页或点击清空时移除。
- `webRequest` 用于观察视频请求；`storage` 用于暂存候选和配对码；HTTP/HTTPS 网站权限用于覆盖网页与视频 CDN，并连接本机服务。可在浏览器管理页限制网站访问，但必须同时允许播放器网页和视频 CDN，否则可能无法捕获。
- 只提取原始请求的 `Referer`，不读取 Cookie 或 Authorization，也不上传云端。点击发送时才把所选地址及 Referer 交给下载器。
- 接收接口为 `http://127.0.0.1:17839/capture`，仅在下载器连接入口开启后监听，使用本机持久保存的随机配对码校验，首次启用后重启自动恢复接收服务。端口可在配对窗口配置；被占用时会提示错误，不接管其他程序的端口。首次启动监听失败时仍可打开配对窗口修改端口。
- 下载器把 Referer 与任务一起保存在现有本地 SQLite 任务库，以便重启后继续下载。视频 URL 可能自带临时签名参数，过期后需重新捕获。

## 限制和排查

- 列表为空：安装后刷新并播放；检查扩展对网页与视频 CDN 的网站访问权限。浏览器内部页面不支持捕获。
- 连接失败：确认下载器运行、连接入口已开启、两端端口一致、保存的配对码正确，关闭下载器中尚未确认的弹窗。第二个下载器实例不能使用同一端口。
- 403 或登录失败：第一版不传 Cookie、Authorization 等登录凭据；仅有网址和 Referer 可能不足以下载。
- 主 M3U8、媒体 M3U8 和广告地址都可能出现在候选列表中。第一版不自动解析清晰度、筛选广告或展开主列表；请选择实际媒体列表。
- 下载器暂不支持加密、字节范围或初始化片段的 M3U8，也不处理 DRM、DASH、`blob:`、WebSocket 等视频来源。直播使用下载器现有能力，不新增持续录制。

## 开发验证

项目根目录运行：

```powershell
node --test extension/tests/*.test.js
python -m unittest discover -s tests -v
```

JavaScript 测试覆盖识别、去重、容量限制、标签页隔离、后台重启与清理；Python 测试使用临时数据库和本地 HTTP 服务验证配对、输入校验、队列、表单预填和真实 MP4 请求头。测试不使用真实视频网站或用户任务库。

真实浏览器验收：加载扩展 → 刷新可播放的测试视频网页 → 播放 → 查看候选 → 复制/发送 → 确认弹窗 → 检查任务。再验证刷新清空、切换标签页隔离、错误配对码提示和下载器关闭后的连接失败。
